# Claude Directory skills-only CLI candidate

The maintained Claude Directory candidate under
[`packaging/claude-directory-skills-only-plugin/`](../packaging/claude-directory-skills-only-plugin/)
contains only plugin metadata, one skill, its byte-identical canonical policy
reference, documentation, a license, and a deterministic inventory. It does
not declare or bundle MCP, a CLI component, hooks, LSP, settings, executables,
scripts, installers, updaters, or `allowed-tools`.

This is a different distribution surface from the local/full Claude plugin.
Users install exact `semantic-scala` `0.1.0-alpha.3` independently through the
public Coursier channel. In Claude Code, the skill teaches Claude to select the existing CLI
through the ordinary shell tool and normal permission flow. It never installs
the CLI or substitutes `semantic-scala-mcp` when the CLI is absent.

## Why this shape is supported

Current first-party guidance says a plugin may contain only skills and that,
when a product already has a public CLI, a plugin may omit a connector and use
skills to teach Claude to call that CLI. The current Plugins API classifies a
plugin with no runtime declarations, settings, or Markdown `allowed-tools` as
contained. The public checklist separately says a command that a skill merely
tells Claude to run is not a bundled runtime script.

- [Choose what to build](https://claude.com/docs/connectors/building/what-to-build)
- [Plugins API reach and upload rules](https://platform.claude.com/docs/en/manage-claude/plugins-api)
- [Pre-submission checklist](https://claude.com/docs/plugins/pre-submission-checklist)
- [Platform support](https://claude.com/docs/plugins/platform-support)
- [Claude Code skills](https://code.claude.com/docs/en/skills)

This supports `SKILLS_ONLY_CLI_SUPPORTED` and a contained package
classification. It does not guarantee public review acceptance or create a
public listing.

## Supported workflow

The candidate exposes the CLI equivalents of the exact eight MCP capabilities:
`compile`, `errors`, `test`, `effect-summary`, `symbol-at`, `symbols`,
`reconcile-symbol`, and `point-evidence`. The included canonical policy remains
authoritative for choosing and interpreting those commands. Its MCP-first
provider rule is replaced only for this package: use the independently
installed CLI and never claim an MCP result.

Build-backed commands can execute project, plugin, or test code, resolve
dependencies, and write outputs or caches. Installing this plugin grants no
permission for those effects. CLI-only commands remain governed by the
canonical policy and are not advertised as part of the Task 268 client proof.

The minimal prerequisite is:

```text
cs install --default-channels=false --channel https://raw.githubusercontent.com/DmytroMitin/scala-semantic-harness/main/distribution/coursier/channel.json semantic-scala
```

Users who separately want the local full MCP integration may install both
applications and configure `semantic-scala-mcp` manually. That MCP integration
is not part of the public skills-only package.

## Surface boundary

- Claude Code is the primary local-CLI surface.
- Cowork can load the skill, but CLI execution is supported only when the
  actual local desktop/session environment exposes the independently installed
  command. The package does not assume that condition.
- Claude chat can load the skill but has no established access to a CLI on the
  user's machine and must not claim local semantic evidence.

## Deterministic package

Run:

```text
python3 -m unittest scripts.tests.test_package_claude_directory_skills_only_plugin
python3 scripts/package-claude-directory-skills-only-plugin.py validate \
  --plugin-root packaging/claude-directory-skills-only-plugin/semantic-scala
python3 scripts/package-claude-directory-skills-only-plugin.py pack \
  --plugin-root packaging/claude-directory-skills-only-plugin/semantic-scala \
  --output /tmp/semantic-scala-claude-directory-skills-only.zip
```

The exact size and digest are generated by the validator and recorded in the
package manifest. It distinguishes archive file entries from files plus
directories in the maintained subtree. Both counts are far below the current
Directory limit, but a later public source repository archive must be validated
again in its entirety.

Claude Code `2.1.220` strict plugin validation passed. An isolated client
session discovered the plugin, its one skill, and zero MCP servers, but the
existing owner-authorized OAuth session expired before the model could run the
semantic treatment. Direct exact-Alpha-3 CLI `effect-summary` and `compile`
corroboration passed, but that is not client-mediated proof. Therefore the
candidate is not yet ready for a public source update or resubmission. A later
qualification must complete the positive effect-summary, build-backed, and
negative no-tool client cases without changing this boundary.

## Existing Directory submission

The skills-only package preserves the same `semantic-scala` name, purpose, and
version family while removing the rejected runtime download/MCP architecture.
It should be prepared as a new version of the existing Needs changes product,
not duplicated as a second listing. The later owner-controlled source-update
task must confirm the public Directory draft accepts that version mapping before
changing the single public source. No source, portal, submission, or listing was
changed while preparing this candidate.
